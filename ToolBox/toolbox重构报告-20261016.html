测试过程中抓到的真 bug（已修） ShellCheck SC2318：local s="$1" ... n=${#s} 与 local i=$1 zone=${TZ_ZONES[$i]} 这类同一条 local 里互相引用的写法， bash 会先展开所有参数再执行 local —— 后者拿到的是外层作用域的值（未定义→空）。 后果：disp_width 把所有 CJK 宽度算错（表格全歪）、tz_set 时区永远取不到、caddy_del 删错行。 拆成多条 local 语句后复测通过。
交付后修正：颜色整体失效（用户截图暴露） 初版把 "\033[34m" 当普通字符串存进变量，再用 printf '%s' 输出——printf 的 %s 不解释反斜杠转义，终端收到的是字面量 \033[34m 文本，所有颜色（含详细模式角标）全部失效。 本地测试全是非 TTY 跑的（自动无色），恰好漏掉这条路径。修正：改用 $'\033[34m' ANSI-C 引用生成真实 ESC 字节，并与六脚本公共区段逐字节对齐（c_* 命名、同一组色码、USE_COLOR + --color 强制开关）； 已补 ESC 字节实测（--color 有输出、--no-color/非 TTY 零输出、色板为六脚本子集），测试总数 42 → 46。
未覆盖的部分（如实说明） 本机是 Windows，以下路径只能静态保证 + 降级路径验证，未经真机执行：root 权限下的 swap/fstab/gai.conf 变更、systemctl 服务管理、 caddy validate、各包管理器安装（apt/dnf/pacman/apk）、第三方安装脚本（tcp.sh/ecs.sh/nezha/soga/XrayR…）。 建议：拿一台测试 VPS 用 --dry-run 全菜单走一遍，确认预览命令符合预期后再实跑。

8有意保留与已知边界

  • 配置 IPv6 菜单：上游两个选项都是「暂时搁置」，重构版不提供半成品，明确标注「计划中」并给出各发行版正确做法指引。
  • ECS 历史结果：上游是空桩。改为扫描 $HOME、/root、当前目录下的 *ecs* 文件列出；ecs.sh 本身不落盘，建议 screen 方式运行自行保存。
  • rar 版本：rarlinux tarball 版本号提为常量 RAR_VERSION="623"，升级只改一行；x64/arm64 按 uname -m 自动选择。
  • 单文件压缩密码：zip -P / 7z -p / rar -p 的密码必然经命令行参数（CLI 固有形态，与上游相同）；screen 批量已改为临时脚本（600）不在 ps 暴露。
  • 哪吒 Key：创建服务时写入 unit 文件（nezha-agent CLI 只支持 -p 传参，与上游相同）；列表展示已脱敏。
  • 与六脚本套件的关系：本文件独立于 ddns/ssh/env/start/proxy/nezha 的 UNIFIED v2 公共区段，未做任何耦合；若将来想让 toolbox 也共用公共区段，需另行评估（会把「单文件」变成「多文件+加载器」）。
