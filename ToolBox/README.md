# toolbox.sh 使用说明

`toolbox.sh` 是一个**交互式 VPS 运维工具箱**：BBR、时区、swap、Caddy、哪吒探针、Aria2、压缩/解压、流媒体与游戏延迟检测等常用操作收进菜单，点数字即可完成。单文件、零依赖配置，下载即可运行。

- 版本：v3.0.0（2026-10-16 重构版，替代旧版 3453 行菜单脚本）
- 仓库位置：`sh/toolbox.sh`；本文档对应仓库 `sh/README-toolbox.md`
- 与 `sh/README.md`（六脚本无人值守部署套件）**互不依赖**：本工具箱是纯交互式日常运维，不读写那套脚本的任何文件

> [!NOTE]
> 旧版用户注意：菜单编号与旧版**完全一致**（系统 1-9 / 软件 1-12 / 科学上网 1-4，各子菜单编号也未变），肌肉记忆不受影响；变化全在内部——详见 [第 10 节](#10-v300-重构说明相对旧版的变化)。

## 1. 环境要求

| 项目     | 要求               | 说明                                                         |
| -------- | ------------------ | ------------------------------------------------------------ |
| Shell    | bash ≥ 4.3         | 脚本带 shebang；用 `sh toolbox.sh` 启动会自动 re-exec 到 bash |
| 网络工具 | curl               | 所有下载走 curl；菜单里也可一键安装 curl                     |
| 权限     | root 或可用 sudo   | 安装软件、改系统配置需要；非 root 时自动垫 sudo              |
| 系统     | 主流 Linux / macOS | 包管理器支持 apt / dnf / yum / pacman / apk / zypper / brew  |

> [!IMPORTANT]
> 不需要（也不建议）先安装任何依赖。除 bash 与 curl 外，screen、unzip、wget 等都可以在「软件菜单」里一键安装。

## 2. 快速开始

推荐先落盘再运行（可以先 review 一遍脚本）：

```bash
curl -fsSL -o toolbox.sh https://raw.githubusercontent.com/RexLee0929/VPS/main/sh/toolbox.sh
bash toolbox.sh
```

也可以一行直接跑：

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/RexLee0929/VPS/main/sh/toolbox.sh)
```

想先看看每个菜单会执行什么命令、不改动系统？加 `--dry-run`：

```bash
bash toolbox.sh --dry-run --yes
```

## 3. 命令行选项与退出码

| 选项              | 作用                                                         |
| ----------------- | ------------------------------------------------------------ |
| `-h`, `--help`    | 显示帮助后退出                                               |
| `-V`, `--version` | 显示版本后退出                                               |
| `--dry-run`       | 演练模式：所有变更只打印将执行的命令与文件写入，不动系统；确认项自动通过 |
| `--verbose`       | 详细模式：打印实际执行的每条命令                             |
| `--yes`           | 所有交互确认自动回答「是」                                   |
| `--no-color`      | 禁用颜色（亦支持 `NO_COLOR` 环境变量；输出不是终端时自动禁用） |
| `--color`         | 强制启用颜色（覆盖「非终端自动禁用」，便于管道/日志留色）    |
| `--self-update`   | 从 GitHub 拉取最新版，语法检查通过后替换自身并重启           |

| 退出码 | 含义                                     |
| ------ | ---------------------------------------- |
| `0`    | 正常退出（包含用户主动跳过、取消的操作） |
| `1`    | 运行错误（下载失败、命令执行失败等）     |
| `2`    | 命令行参数错误                           |

> [!TIP]
> `--dry-run --yes` 组合可以全自动预览整个菜单树会做的事，适合升级前评估影响面。

## 5. 系统设置（主菜单 1）

| 编号 | 功能            | 说明与注意事项                                               |
| ---- | --------------- | ------------------------------------------------------------ |
| 1    | BBR加速         | 下载并运行第三方脚本 `tcp.sh`（chiakge/Linux-NetSpeed），交互式选择内核与加速方案，装完需重启 |
| 2    | 设置时区        | 基于 `timedatectl`，6 个常用时区；已设置过同一时区会提示跳过 |
| 3    | 设置swap        | 创建 `/swapfile` 并写入 fstab（带 `sw` 选项，重启生效）；删除时只动 `/swapfile` 条目，不会误删 fstab 其他行、不会关掉 zram；`fallocate` 失败自动回退 `dd`；OpenVZ 架构会明确提示不支持 |
| 4    | IPv4/IPv6优先级 | 改 `/etc/gai.conf`；文件不存在时自动创建；「验证」项通过 `ip.p3terx.com` 显示当前出口地址类型 |
| 5    | 配置IPv6        | 旧版搁置项，本版如实标注「计划中」，不提供半成品             |
| 6    | 融合怪ECS       | 跑 spiritLHLS/ecs.sh；screen 方式适合长任务；「查看历史结果」扫描 `$HOME`、`/root`、当前目录下的 `*ecs*` 文件（ecs.sh 默认不落盘，建议 screen 方式自行保存输出） |
| 7    | FinalShell增强  | 安装 df 包装脚本，`df` 默认过滤 overlay 类型（docker 挂载路径）；安装前自动备份原 `/usr/local/bin/df`，「恢复」优先还原备份 |
| 8    | 流媒体检测      | lmc999/RegionRestrictionCheck，可选 IPv4/IPv6 出口分别检测   |
| 9    | 游戏延迟检测    | lmc999/GamePing，直接运行                                    |

## 8. 压缩包驱动详解

unzip、7zip、rar 三个菜单结构完全相同（1-8 编号一致）：

| 编号 | 功能            | 说明                                                         |
| ---- | --------------- | ------------------------------------------------------------ |
| 1    | 安装            | 按包管理器安装；RHEL 系没有官方 rar 源，自动改用 rarlab 官方 tarball（按 `uname -m` 选 x64/arm64），卸载时清理 `/usr/local/rar` 与符号链接 |
| 2    | 解压文件        | 单文件解压到指定目录，支持密码                               |
| 3    | 压缩文件夹      | 把整个文件夹压成一个包，支持密码                             |
| 4    | 批量解压        | 解压目录下全部压缩包；密码可选「统一密码」或「逐个输入」     |
| 5    | 批量压缩        | 压缩目录下所有子文件夹，各生成一个包；密码模式同上           |
| 6    | screen 批量解压 | 后台 screen 会话执行，断线不中断；会话名 `tb_unzip` / `tb_un7z` / `tb_unrar` |
| 7    | screen 批量压缩 | 同上；会话名 `tb_zip` / `tb_7z` / `tb_rar`                   |
| 8    | 卸载            | 见编号 1 说明                                                |

密码交互规则：

- 「所有文件是否使用相同的密码？」直接回车 = 统一密码（再问一次，回车 = 无密码）；输入任意字符 = 逐个文件询问。
- 单文件解压/压缩直接询问密码，回车 = 无密码。

> [!TIP]
> screen 批量任务会生成一个权限 600 的临时脚本来执行，密码**不会**出现在 `ps` 命令行里（旧版是拼进 `bash -c` 字符串的，既容易转义错也容易泄露）。任务脚本位于临时目录，退出工具箱时自动删除；会话内可用 `screen -r <会话名>` 查看进度。

> [!NOTE]
> Alpine 的 rar 菜单只装 `unrar`（只能解压）；需要压缩请用 7zip。
> rar 版本号是脚本内常量 `RAR_VERSION`（当前 `623`），升级只改这一行。

## 9. 安全机制

| 机制       | 说明                                                         |
| ---------- | ------------------------------------------------------------ |
| 演练模式   | `--dry-run` 下所有变更操作只打印将执行的命令与文件写入，不落地 |
| 改动前备份 | 改 fstab、gai.conf、Caddyfile、service 文件、`/usr/local/bin/df` 前自动备份为 `<文件>.tb-时间戳.bak`；同一次运行同一文件只备份一次 |
| 下载校验   | 所有第三方脚本下载到 `mktemp -d` 临时目录，`curl -fsSL --retry 2`，校验非空才执行；退出时自动清理，不污染当前目录 |
| 最小权限   | 非 root 且存在 sudo 时自动垫 sudo；既非 root 又无 sudo 时明确报错，不静默失败 |
| 敏感信息   | 哪吒 Key 列表脱敏显示；screen 批处理密码走临时脚本（600）不进命令行 |
| 退出码     | 0 正常 / 1 运行错误 / 2 参数错误，可接入脚本化判断           |

## 10. v3.0.0 重构说明（相对旧版的变化）

菜单编号与交互流程保持不变，主要变化在正确性与可维护性：

| 类别   | 旧版问题                                                     | 本版                                                         |
| ------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 正确性 | 17 个功能性 bug：`cmd=` 后带空格致 screen 批量解压不可用、rar 分支变量转义错、aria2 修复写空文件毁服务、screen 菜单误跳 nano、fstab 误删行且缺 `sw` 选项、Caddy 删除多删一行、哪吒删除不校验序号等 | 全部修复，并有自动化测试覆盖                                 |
| 入口   | 无 shebang，`sh toolbox.sh` 直接语法错误                     | shebang + bash 版本守卫 + 自动 re-exec                       |
| 结构   | 菜单靠函数递归（误输入还会双重递归），24 处重复系统检测，3 份约 150 行的重复压缩包菜单 | 数据驱动菜单引擎（while 循环）+ 包管理器抽象 + 单一压缩包驱动，代码 3453 → 2132 行 |
| 安全   | 明文 HTTP 下载安装器、`--no-check-certificate`、密码进 `ps`、改系统文件从不备份 | HTTPS、去掉跳过证书校验、临时脚本承载密码、改动前自动备份    |
| 体验   | 黑字「卸载」选项在深色终端不可见、CJK 表格列宽错位、正常退出返回 1 | 灰色替代、CJK 列宽按显示宽度计算、退出码规范化               |
| 可观测 | 无预览能力                                                   | `--dry-run` / `--verbose` / `--self-update`                  |

> [!NOTE]
> 颜色与六脚本套件（`start.sh` 等）**同一套定义**：`c_red/c_green/c_yellow/c_blue/c_orange/c_cyan/c_gray/c_bold/c_reset`，取值分别为 `\033[31m/32m/33m/34m/38;5;208m/36m/90m/1m/0m`，并用 `$'\033[...]'` ANSI-C 引用生成真实转义字节；优先级为 `--color` > `--no-color` > `NO_COLOR` > 非 TTY 自动禁用。上游的紫色（重复操作提示）与黑字（深色终端不可见）已分别并入青、灰，全库只剩这一套 7 色。

## 11. 常见问题

**Q：用 `sh toolbox.sh` 运行报错？**
需要 bash（≥ 4.3）。脚本检测到非 bash 会自动 `exec bash` 重新启动；若仍失败，请直接 `bash toolbox.sh`，或 `chmod +x toolbox.sh && ./toolbox.sh`。

**Q：没有颜色 / 颜色乱码？**
加 `--no-color`，或设置 `NO_COLOR=1`。输出被重定向到文件或管道时脚本会自动禁用颜色；想在日志里保留颜色用 `--color`。颜色定义与六脚本套件完全一致（详见[第 10 节](#10-v300-重构说明相对旧版的变化)）。

**Q：非 root 用户能做什么？**
能跑的都会自动用 sudo；查看类功能（如 Caddy 配置查看、哪吒列表）不需要 root。既非 root 又无 sudo 时，涉及特权的菜单会明确提示并退出该项。

**Q：提示「已存在 /swapfile」？**
先到「系统菜单 → 3 设置swap → 5 删除swap」删掉旧的再创建。

**Q：Caddy 改完配置不生效？**
「Caddy → 5 Caddy 重新加载」。删除配置后如果 `caddy validate` 报警告，脚本会提示，按提示检查 `/etc/caddy/Caddyfile`（改动前的 `.bak` 备份在同目录）。

**Q：哪吒列表里 Key 是星号？**
脱敏显示，完整值在 `/etc/systemd/system/nezha-agent*.service` 的 `ExecStart` 行。

**Q：menu 编号和旧版一样吗？**
一样。系统 1-9、软件 1-12、科学上网 1-4，子菜单编号也未变；唯一变化是软件菜单第 9 项名称从「Nezha Panel」改为「Nezha Agent」（它管理的本来就是 Agent）。

**Q：如何升级？**
`bash toolbox.sh --self-update`（自动拉取最新版、语法校验、替换并重启），或重新下载覆盖。
